**What was built:**
- `refresh_tokens` table to store and revoke refresh tokens
- `POST /api/auth/register` — creates viewer accounts only
- `POST /api/auth/login` — validates credentials, returns access + refresh token
- `POST /api/auth/refresh` — verifies refresh token in DB, returns new access token
- `POST /api/auth/logout` — deletes refresh token from DB permanently
- `GET  /api/auth/me` — returns current user profile (requireAuth protected)
- `POST /api/auth/create-staff` — super_admin only, creates admin/camera_op accounts

**How auth flow works:**
```
Login → gets accessToken (15min) + refreshToken (7 days)
Every API request → sends Authorization: Bearer <accessToken>
After 15min → frontend calls /refresh with refreshToken → gets new accessToken
Logout → refreshToken deleted from DB, can never be used again
```

**Key facts to remember:**
- Passwords are hashed with bcrypt (10 rounds) — never stored plain
- `sanitizeUser()` strips `password_hash` before sending to frontend
- Single session: old refresh tokens deleted on each new login
- Access token expiry: 15 minutes
- Refresh token expiry: 7 days stored in `refresh_tokens` table
- Same error message for wrong email AND wrong password (security)

#### events.routes.js
```
GET    /api/events           List all events. Supports ?status= and ?featured=true filters.
                             Public — no auth required.
                             Join with users table to include created_by_name.
                             Sort by starts_at ASC.

GET    /api/events/:id       Single event by ID.

POST   /api/events           Create a new event.

                             Optional: description, location, thumbnail_url, ends_at, is_featured.
                             Validate starts_at is a valid date.

PUT    /api/events/:id       Update an existing event.
                             requireAuth + requireAdmin.
                             Fetch existing first, use existing values as defaults.
                             Validate status is one of: upcoming|live|ended|cancelled.

DELETE /api/events/:id       Delete an event.
                             requireAuth + requireAdmin.
                             Return 404 if not found.
                             Return success message.
```

#### stream.routes.js
```
GET    /api/stream/status    Get current stream state.
                             Public — no auth.
                             IMPORTANT: never include stream_key in this response.
                             Return: id, is_live, title, description, event_id,
                                     active_camera, chat_enabled, viewer_count, started_at.

POST   /api/stream/start     Start the live stream.
                             requireAuth + requireSuperAdmin.
                             Required: title.
                             Optional: description, event_id.
                             UPDATE stream_status SET is_live=true, title=..., started_at=now().
                             Also UPDATE linked event status to 'live' if event_id provided.
                             After DB update: broadcast WebSocket event { type: 'stream.live' }.
                             After broadcast: fire n8n webhook (non-blocking, don't fail if n8n is down).

POST   /api/stream/end       End the live stream.
                             requireAuth + requireSuperAdmin.
                             Check stream is actually live first — throw AppError if not.
                             UPDATE stream_status SET is_live=false, ended_at=now().
                             Also UPDATE linked event status to 'ended' if event_id exists.
                             Broadcast { type: 'stream.ended' }.
                             Fire n8n end webhook (non-blocking).

PATCH  /api/stream/camera    Switch the active camera.
                             requireAuth + requireAdmin.
                             Body: { camera: 'cam1' | 'cam2' | 'cam3' }.
                             Validate camera slot is one of cam1/cam2/cam3.
                             UPDATE stream_status SET active_camera = $1.
                             Broadcast { type: 'stream.camera_switch', data: { active_camera } }.

PATCH  /api/stream/chat      Toggle chat on or off.
                             requireAuth + requireAdmin.
                             Body: { enabled: true | false }.
                             UPDATE stream_status SET chat_enabled = $1.
                             Broadcast { type: 'stream.chat_enabled' } or { type: 'stream.chat_disabled' }.

GET    /api/stream/key       Get the secret stream key.
                             requireAuth + requireSuperAdmin.
                             Returns stream_key — this is the ONLY endpoint that exposes it.
```

#### chat.routes.js
```
GET    /api/chat/:streamId   Fetch chat history for a stream session.
                             Public — no auth.
                             Only return messages where is_deleted = false.
                             Order by created_at ASC.
                             Limit to last 100 messages.

POST   /api/chat             Send a chat message.
                             requireAuth (any logged-in user).
                             Body: { message, stream_id }.
                             Validate: message is 1–500 characters.
                             Check stream is currently live — reject if not.
                             Check chat_enabled = true — reject if disabled.
                             INSERT into chat_messages.
                             Broadcast { type: 'chat.message', data: { message object } }.

DELETE /api/chat/:messageId  Soft delete a message (admin moderation).
                             requireAuth + requireAdmin.
                             UPDATE chat_messages SET is_deleted=true, deleted_by=..., deleted_at=now().
                             Broadcast { type: 'chat.message_deleted', data: { message_id } }.
```

#### recordings.routes.js
```
GET    /api/recordings       List recordings.
                             Public — returns only is_public=true AND processing_status='ready'.
                             Admin requests (if logged in as admin) return all recordings.
                             Order by recorded_at DESC.
                             Join with events table for event title.

GET    /api/recordings/:id   Single recording.
                             Public can only see public+ready recordings.
                             Admin can see all.
                             Return 404 if not found or not accessible.

PATCH  /api/recordings/:id   Update recording metadata.
                             requireAuth + requireAdmin.
                             Updateable fields: title, description, is_public.
                             Do not allow changing file_url or s3_key.

DELETE /api/recordings/:id   Delete a recording.
                             requireAuth + requireAdmin.
                             Delete from DB.
                             NOTE: S3 file deletion will be wired up in Step 10.
```


**What was built:**
- POST /whip endpoint accepting SDP offer + X-Camera-Slot header
- Server-side RTCPeerConnection creation using wrtc package
- SDP answer returned with all ICE candidates bundled (no trickle ICE)
- ICE gathering with 2-second timeout for slow networks

- activeConnections map exported for mixer (Step 9) to access later
- Graceful handling: closes previous connection on same slot before accepting new one

**What to build:**
- WHIP (WebRTC-HTTP Ingest Protocol) endpoint at `POST /whip`
- Accepts WebRTC offer SDP from the broadcaster's browser
- Creates a WebRTC peer connection on the server side
- Returns answer SDP to the browser
- When ICE negotiation completes, media starts flowing
- Pipes incoming video/audio tracks into FFmpeg (Step 7)
- Emits `camera.connected` event to API server when feed established
- Emits `camera.disconnected` event when feed drops

**WHIP flow:**
```
Broadcaster browser → POST /whip with SDP offer + camera slot header
Media server creates RTCPeerConnection
Media server returns SDP answer
ICE candidates exchanged
Video/audio tracks arrive at media server
Tracks piped to FFmpeg transcoder
```

**Important:** The WHIP endpoint needs to know WHICH camera slot this connection is for.
The broadcaster sends a custom header: `X-Camera-Slot: cam1` (or cam2/cam3).

**What was built:**

- FFmpeg spawned per quality level with libx264, veryfast preset, zerolatency tune
- HLS output: 2-second segments, rolling window of 10, auto-delete old segments
- startTranscoding(slot) / stopTranscoding(slot) lifecycle management
- Master playlist generator (master.m3u8 with all quality levels)
- HLS directory cleanup for stream end
- HTTP endpoints for internal control: /transcoder/start, /transcoder/stop, /packager/generate-master, /packager/cleanup
- WHIP endpoint automatically starts transcoding when camera connects, stops when it disconnects

**What to build:**

The transcoder receives raw video/audio frames from the WebRTC connection
and feeds them into FFmpeg which outputs HLS segments.

```
WebRTC track (raw frames)
        ↓
FFmpeg process (spawned as child process)
        ↓ (3 parallel outputs)
1080p @ 4Mbps  → /var/hls/1080p/stream.m3u8
720p  @ 2Mbps  → /var/hls/720p/stream.m3u8
480p  @ 1Mbps  → /var/hls/480p/stream.m3u8
240p  @ 400kbps → /var/hls/240p/stream.m3u8
        ↓
Master manifest → /var/hls/master.m3u8
```

**FFmpeg settings to use:**
- Codec: `libx264`
- HLS segment duration: 2 seconds
- HLS list size: 10 (rolling window — keeps last 10 segments)
- HLS flags: `delete_segments` (auto-deletes old segments)
- Preset: `veryfast` (low CPU latency — important for live)
- Tune: `zerolatency`

**Packager** generates the `master.m3u8` file that points to all quality levels.
This is what HLS.js loads first when a viewer opens the watch page.

**HLS output directory:** `/var/hls/` on the VPS.
Nginx serves this directory as static files to viewers.

## COMMON ERRORS AND FIXES

| Error | Cause | Fix |
|---|---|---|
| `permission denied for table users` | PostgreSQL user missing grants | Run the GRANT commands in Step 3 notes |
| `JWT malformed` | Sending wrong token format | Check `Authorization: Bearer <token>` format |
| `Cannot connect to database` | PostgreSQL not running | `sudo systemctl start postgresql` |
| `EADDRINUSE port 4000` | Server already running | Kill old process: `lsof -ti:4000 \| xargs kill` |
| `nodemon not found` | Dev dependencies not installed | `npm install` in api-server folder |
| `Cannot find module` | Missing require path | Check relative path in require() statement |
| `invalid input syntax for type uuid` | Passing invalid UUID | Validate UUID format before DB query |
